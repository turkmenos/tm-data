# Dataset quality summary

[`summary.json`](summary.json) is generated by [`tools/quality`](../../tools/quality/README.md)
from the current data files, [`catalog.json`](../../catalog.json),
[`tools/integrity/rules.json`](../../tools/integrity/rules.json), and
[`tools/quality/config.json`](../../tools/quality/config.json). Do not edit it by hand:

```sh
go run ./tools/quality
```

## Structure

| Field | Meaning |
| --- | --- |
| `schema_version` | Report schema version, currently `1.0.0` |
| `status` | `passed`, `warning`, or `error` for the whole repository |
| `inputs` | Repository-relative paths of the files the report was built from |
| `totals` | Dataset counts per status, plus the total `errors` and `warnings` |
| `datasets[]` | One entry per catalog dataset, in catalog order |
| `repository` | Format problems in files outside any dataset |
| `limitations` | What the report does not prove |

Each `datasets[]` entry contains:

| Field | Meaning |
| --- | --- |
| `dataset`, `title`, `location`, `version` | Copied from `catalog.json`; `version` identifies the data snapshot checked |
| `record_count`, `record_unit` | Sum of the configured catalog resources; `null` when unknown, `mixed` when units differ |
| `status` | `error` if any error, else `warning` if any warning, else `passed` |
| `checks` | `utf8`, `syntax`, `duplicates`, `schema`, `references`, `metrics`: each `passed`, `failed`, or `not_configured` |
| `metrics` | Counts below |
| `error_count`, `errors[]` | Full error total and the first 100 findings (`path`, optional 1-based `record`, `check`, `kind`, `message`) |
| `warnings[]` | Human-readable warnings, sorted |

| Metric | Meaning |
| --- | --- |
| `files_checked` | JSON, JSONL, GeoJSON, and CSV files checked for format problems |
| `invalid_utf8_files` | Files that are not valid UTF-8 |
| `syntax_errors` | Malformed files, duplicate JSON keys, or duplicate CSV headers |
| `duplicate_records` | Identical records plus duplicate unique keys |
| `missing_required_fields` | Required, non-empty, or alternative-required field violations |
| `schema_violations` | All schema violations, including missing required fields |
| `referential_integrity_errors` | Broken cross-file references |
| `unverified_records` | Records whose verification status is not a configured verified value |
| `missing_sources` | Records with no configured source field filled |
| `missing_coordinates` | Records missing a configured coordinate field |

A metric is `null` when no rule or configuration covers it for that dataset.
`null` means unknown, not zero.

## Limitations

The report measures structure and documented completeness. A `passed` status
does not prove factual accuracy, source reliability, or redistribution rights.
Warnings for unverified records and missing coordinates reflect the current
state of the data and are expected until sources are added.
